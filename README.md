# 프로젝트 개요

암은 유전자 수준에서 발생하는 다양한 변이(mutation)에 의해 아형(subtype)이 결정되며, 아형에 따라 치료 방침과 예후가 크게 달라집니다.
본 프로젝트는 환자별 유전자 변이 프로파일을 활용해 암의 아형(SUBCLASS)을 예측하는 다중 분류(multi-class classification) 모델을 개발하는 것을 목표로 합니다.

- **과제**: 유전자 변이 정보 기반 암 아형(SUBCLASS) 예측
- **문제 유형**: 다중 분류 (Multi-class Classification)
- **평가 지표**: Macro F1 Score
- **최종 결과**: CV 0.4641 (OOF 0.4651) / **LB 0.3792**

# 데이터 전처리

1. **빈칸 처리**: test의 빈칸은 `WT`로 채움 (고정 규칙)
2. **변이 표기 통일** (HGVS 표준 표기 규칙, train과 test에 같은 고정 규칙 적용)
   - 정지코돈 `X` → `*` (예: `R492X` → `R492*`)
   - 프레임시프트 뒤 아미노산 제거 (예: `K600Nfs` → `K600fs`)
3. **피처 생성** (`src/features.py`)
   - `any`: 유전자별 변이 유무 이진화 (0/1)
   - `ratio`: 변이 유형별 비율 (in-frame indel 포함) + 변이 수(log)
   - **미스센스 치환 종류 비율**: 환자의 미스센스 중 `R>H`, `E>K` 같은 치환 종류가 차지하는 비율. 상위 100개 목록은 fold 학습 부분에서만 선택
     - 근거: 암을 만든 원인(흡연, 자외선, DNA 복구 고장 등)마다 잘 생기는 치환 종류가 다름 (Alexandrov et al., Nature 2013)
4. **Data Leakage 방지 원칙**
   - 변이 빈도, 상위 N개 목록, 표준화 등 데이터에서 무언가를 배우는 과정은 모두 fold 학습 부분으로만 계산
   - test 값은 학습·튜닝·피처 선택에 쓰지 않음
   - 전처리 규칙도 test를 보고 만들지 않음 (아래 누수 점검 참고)
   - 사용하지 않은 방법: 중복 환자 라벨 교정, 예측 비율을 train 비율에 맞추는 후처리, test 빈도로 유전자 빼기

### 누수 점검 (11/13)

데이터 누수 공지 기준으로, 전처리마다 "그 규칙을 무엇을 근거로 만들었는가"를 점검했습니다.

| 전처리 | 만든 근거 | 최종 |
|---|---|:-:|
| 정지코돈 `X` → `*` | HGVS 표준 표기 | 유지 |
| fs 뒤 아미노산 제거 | HGVS 표준 표기 | 유지 |
| 이소폼 중복 제거 | test 패턴을 보고 만듦 | **제거** (`load_data(dedupe=False)`) |
| 비율 피처에서 in-frame indel 분모 제외 | test 개수를 보고 정함 | **제거** (indel 포함) |

- 두 규칙을 빼자 LB 0.3660 → **0.3792** (+0.013), CV 0.4686 → 0.4641 (시드 차이 수준)
- 두 규칙을 함께 빼서, LB 상승이 어느 쪽 때문인지는 가려내지 못함 (train에는 해당 패턴이 거의 없어 CV로 확인 불가)
- ⚠️ `src/data.py`의 `load_data()` 기본값은 아직 `dedupe=True`라서, 최종 방식으로 실행하려면 `load_data(dedupe=False)`로 불러야 함

# 모델링

- **최종 모델**: XGBoost 0.7 + 로지스틱 회귀 0.3 확률 섞기
  - XGBoost: `any` + `ratio` + 미스센스 치환 종류 비율(상위 100)
    - max_depth=3, learning_rate=0.1, n_estimators=200, colsample_bytree=0.3
    - 시드 5개(42, 7, 123, 2024, 777) 확률 평균
  - 로지스틱 회귀: `any`, `class_weight='balanced'`, C=0.1
- 클래스 불균형: 모든 모델에 balanced 가중치 적용 (XGBoost는 fold 학습 부분 기준 sample_weight)
- 비교한 모델: LightGBM, RandomForest, ExtraTrees, MLP·Transformer (최종에는 미사용)

### 실험에서 얻은 교훈

1. **CV와 LB가 자주 어긋남**: 피처를 추가해서 오른 CV는 LB로 넘어가지 않는 경우가 많았음
   - LB로 넘어감: LR → XGBoost(+0.026), 깊이·피처 샘플링 줄이기(+0.021), LR 섞기(+0.0045), 치환 종류 비율(+0.040), test 기반 규칙 제거(+0.013)
   - 넘어가지 않음: 변이 개수 피처, 핫스팟, 희귀 유전자 제거, 앙상블 선택
2. **개수가 아니라 어떤 종류인지가 중요했음**: 유형별 개수를 비율로만 바꾼 22a는 실패했고, 미스센스 치환 종류 비율(22b)을 넣자 처음으로 CV 상승이 LB까지 그대로 넘어감
3. **같은 재료도 어디에 넣느냐가 중요함**: 치환 비율을 XGB에 넣으면 LB 0.3650, LR에만 넣으면 0.3324, 둘 다 넣으면 정보가 겹쳐 CV 하락
4. **섞기 효과는 대부분 LR에서 나옴**: XGBoost와 예측이 다른 비율이 42%로 가장 높은 모델이 LR. 같은 부스팅 계열인 LightGBM은 넣으면 오히려 하락
5. **시드와 컴퓨터만 바꿔도 점수가 흔들림**
   - 같은 코드에서 XGB 시드만 바꾼 섞기 CV 0.4187 ~ 0.4237, macOS와 Windows의 XGB CV 차이 0.0036
   - 열 구성이나 실행 환경이 바뀌면 CV가 ±0.005~0.01 움직임 → 이 범위 안의 상승은 효과로 보지 않음
   - 그래서 만든 규칙: XGB 시드 평균, 재현 스크립트, 제출 파일은 Windows 데스크탑 한 대에서만 생성
6. **전처리 규칙도 근거를 기록해야 함**: test를 보고 만든 규칙을 빼자 오히려 점수가 올랐음

# 최종 모델

- **v2: 치환 비율 XGB(시드 5개 평균) 0.7 + LR 0.3, test 기반 규칙 제거**
  - CV 0.4641 (OOF 0.4651) / LB 0.3792
  - 제출 파일: `1113_blend_ratio22sub100_seed5_0.7_LR0.3_nodedupe_0.465.csv`
  - 제출 코드: `notebooks/22_final_submission.ipynb`

- 선택 이유
  1. 팀 최고 LB이면서, test를 보고 만든 전처리가 하나도 남지 않은 설정
  2. 시드 5개 평균이라 시드 하나에 따른 흔들림을 줄임
  3. 시드 10개 버전(32번)은 CV는 비슷하고 LB가 0.002 낮아 흔들림 범위로 판단, v2 유지

### 한계

1. 같은 환자가 두 라벨로 들어 있어 점수에 상한이 있음
   - train의 16.2%(1,005행)는 변이가 똑같지만 라벨이 다름. 완벽한 모델이라도 Macro F1 0.94 (정확도 91.8%)가 최대
2. 변이가 없는 환자는 변이 데이터만으로 구분할 근거가 없음
   - 변이 0개 환자 94명은 모두 THYM으로 예측됨. 다른 암종으로 바꾸거나 THYM 확률을 낮추면 교차 적합 CV가 모두 떨어져 그대로 둠
3. test 기반 규칙 2개를 함께 제거해, LB 상승 요인이 어느 쪽인지 가려내지 못함

# 실행 방법

- 개발 환경 (최종 제출 파일 생성)
  - Windows 11 Home 26H2, AMD Ryzen 5 5600
  - Python 3.14.2, xgboost 3.4.1, scikit-learn 1.9.1, pandas 3.1.1, numpy 2.5.4
  - macOS M1, Python 3.12.14에서도 실행 확인 (XGB CPU 차이로 CV +0.0007)

- 환경 설치
  ```bash
  pip install -r requirements.txt
  ```

- 데이터 준비
  - 대회 데이터(`train.csv`, `test.csv`, `sample_submission.csv`)를 `data/` 폴더에 넣기

- **최종 제출 재현**
  - `notebooks/22_final_submission.ipynb`를 처음부터 끝까지 실행
  - `src/`를 불러오지 않고 노트북 하나에 전처리 → 피처 → 검증 → 학습 → 저장이 모두 들어 있음 (data 폴더만 있으면 실행)
  - 저장된 모델 파일 없음 (실행 시 처음부터 학습), 사전 학습 모델·외부 데이터 사용하지 않음

  - 실험 과정은 `notebooks/` 번호 순서로 실행
  - 각 노트북은 `src/validation.py`의 `run_cv`로 CV를 계산하고, `save_submission`으로 `submissions/`에 제출 파일을 저장
  - `scripts/train_blend.py`는 14번 섞기 단계까지의 재현 기록용 (`--preset blend14`, `select6`). 최종 모델은 위 노트북으로 재현
